# Contributing

Contributions must preserve the distinction between reusable A1Web policy and product-specific rules.

## Requirements

- Keep standards generic enough for more than one product.
- Do not copy product-specific release gates into reusable policy.
- Add or update an ADR when changing a durable architectural decision.
- Keep examples tool-neutral unless a standard explicitly targets a tool.
- Do not commit secrets, customer data, credentials, certificates, private keys, provisioning profiles, store credentials, or proprietary editable marketing masters.

## Review

Changes require review by the repository owners named in `GOVERNANCE.md`.

Adopting products decide independently when to update from one published standards version to another.
